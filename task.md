# #52. Открывать файлы в отдельных окнах NimMD

## Цель и источники

Пользователь открывает локальный файл из терминала, Finder или перетаскиванием на окно NimMD. У каждого открытого файла отдельное окно. Повторный запрос переводит его окно на передний план. Источники — снимок [issue №52](https://github.com/syper-freedm/NimMD/issues/52), спецификация `docs/superpowers/specs/2026-10-19-nimmd-design.md`, §5.4 «Окно» (Р18, в issue обозначено О18) и §9. Зависимость #51 представлена парсером CLI, окном, IPC и ассоциациями в поставленном снимке.

В объём входит привязка окна к файлу и показ соответствующих параметров запуска в существующем интерфейсе. Чтение содержимого, редактор, сохранение, индикатор изменений, прокси-иконка, вкладки, восстановление набора окон и Quick Look относятся к другим задачам. Уточнение владельца в §5.4 от 2026-11-18 распространяет Р18 на прямые повторные вызовы CLI в том же пользовательском сеансе. После выхода первичного экземпляра следующий вызов может запустить новый. Область включает `apps/desktop/src-tauri/Cargo.toml` и `Cargo.lock` для прямого подключения уже закреплённого `rustix` 1.1.5 с файловым API.

## Функциональные требования

- **FR-1.** Сохранить синтаксис `nimmd [--view] [--] файл` и пустой запуск. CLI принимает один путь и выбирает режим по прежним правилам. Относительный путь разрешается в рабочем каталоге вызывающего процесса. Если NimMD уже запущен в этом сеансе, CLI передаёт запрос этому экземпляру и завершается после ответа о результате. Запрос с файлом передаёт путь и режим. Запрос без аргументов восстанавливает и активирует существующее пустое окно либо создаёт его, если такого окна нет. Finder доставляет локальные файловые URL в `RunEvent::Opened`. Перетаскивание обрабатывается в момент сброса на любое окно NimMD. Finder и drop по умолчанию открывают окно в режиме редактирования, как CLI без `--view`. Это допущение для каркаса, где отображаются только параметры запуска. Роли Viewer и Editor остаются в метаданных бандла. Правило выбора режима для файлов данных при подключении просмотра содержимого определяется в соответствующей задаче (§5.7).
- **FR-2.** Каждый успешный запрос к новому файлу получает своё окно. При явном запуске без файла остаётся пустой экран «Файл не выбран», на который можно сбрасывать файлы. Успешное холодное открытие документа из Finder оставляет только файловое окно. Уже показанный пользователю пустой экран сохраняется при последующем открытии файла. Файловое окно получает публичный заголовок, равный последнему компоненту пути с расширением. Экран внутри окна показывает режим и путь именно этого окна.
- **FR-3.** Для идентичности файла используется канонический локальный путь. В IPC передаётся UTF-8 путь, принятый при первом открытии. Повторные запросы через альтернативные пути его не меняют. Относительный и абсолютный путь, а также символьная ссылка на одну цель дают одно окно. Разные каталоги с одинаковым именем файла дают разные окна. Если пользователь открыл файл через символьную ссылку, имя первого принятого пути задаёт заголовок. Жёсткие ссылки и Finder aliases не входят в гарантии дедупликации. Повторный запрос сохраняет текущий режим и параметры окна, восстанавливает свёрнутое окно и активирует его. После фактического закрытия файл можно открыть снова. Если найденное окно закрылось до завершения активации, тот же запрос создаёт новое окно в запрошенном режиме. При сбое создания нового или активации ещё живого окна применяется FR-4.
- **FR-4.** Обработать все элементы одного Apple Event или drop независимо. Для отсутствующего пути, каталога, неподдерживаемого формата URL, пути с неподдерживаемой кодировкой или сбоя создания окна показать причину и способ повторить открытие. Ошибка CLI видна на stderr с ненулевым кодом. Если после отправки полного запроса истёк срок ожидания ответа, stderr сообщает, что результат неизвестен и приложение ещё может выполнить запрос. Перед повтором пользователь может проверить окно. При сбросе ошибка видна в окне, на которое сбросили файлы. При открытии из Finder причина и подсказка видны на переднем плане при холодном и тёплом запуске, в том числе когда окна NimMD скрыты или свёрнуты. Если пригодного окна нет, приложение показывает резервное окно. После сообщения можно повторить открытие тем же способом. Пример для каталога — «Не удалось открыть „notes“. Выберите файл.» Для недоступного пути — «Не удалось открыть „note.md“. Проверьте, что файл существует и доступен, затем откройте его снова.» Ошибки пакета можно показать одним сообщением с именами и причинами. Успешно открытые окна сохраняются.

## Точки входа, реализация и границы доверия

Переиспользовать парсер, формат DTO и frontend запуска.
- Объединить входы в Rust-слое `app/`. Основа — реестр по каноническому пути с данными окна по внутренней метке, доступными до первого IPC. Для проверки версии Rust использован непосредственно бинарник установленного toolchain. Для реализации использовать закреплённый стек.

Первичный источник API — локальные исходники точных версий из Cargo registry. В `tauri-2.11.6/src/app.rs` подтверждены `RunEvent::Opened { urls }`, `WindowEvent::Destroyed` и обработчики окон.
