# #53. Сделать режим просмотра nimmd --view

## Цель и объём

`nimmd --view файл` открывает локальный Markdown или файл данных для чтения в отдельном окне. Приложение показывает результат общего ядра с темой Quick Look. Поддерживаемые расширения — `.md`, `.markdown`, `.mdown`, `.mkd`, `.toml`, `.yaml`, `.yml`, `.json`, `.csv`, `.txt`. Источники — снимок [issue №53](https://github.com/syper-freedm/NimMD/issues/53), переданные координатором выдержки спеки §5.4 (стр. 680–695), §5.7 (754–768) и §9 (970–977), API и README ядра.

Оконные точки входа и правило сохранения режима при повторном открытии наследуются от #52. Редактор и его первый кадр, Quick Look, пользовательские изображения и протокол `nimmd-asset://`, публикация `/vendor` в штатной сборке и CSP для ресурсов (#54), замер холодного старта (#55) и автообновление открытого документа находятся за пределами задачи. #53 определяет пути потребления `/vendor`. Для приёмки этих путей используется набор локальных ресурсов #42, временно поданный со штатного origin в тестовом окружении. В существующей сборке Mermaid меняется выбор ELK на dagre. Предыдущий контракт #52 сохранён в `88c9f835aeb86a7b435438aab36d8d070937de73:task.md`.

## Функциональные требования

- **FR-1.** При создании окна в `Mode::View` использовать отдельную HTML-точку входа Vite. Сразу показать короткий текст загрузки, затем содержимое. Имя файла в нативном заголовке, отдельные окна для разных файлов, восстановление фокуса и исходный режим при повторном открытии работают как в #52. При первом открытии файла данных через CLI без `--view`, через Finder или перетаскиванием используется текущий каркас в `Mode::Edit`. Для нового окна `Mode::View` выбирается явным флагом `--view`. Пустой запуск по-прежнему открывает каркас.
- **FR-2.** Tauri-команда возвращает только `Rendered.body` текущего окна в режиме просмотра. Rust читает обычный локальный файл, уже привязанный к окну. Команда определяет режим и путь по контексту окна и реестру. Чтение выполняется из проверенного обычного файла. Файловый ввод-вывод и рендер происходят вне главного потока и вне блокировки реестра. Ядро получает строку из `text::decode_lossy`, `not_utf8`, `FileKind::from_extension` без учёта регистра расширения, тему Auto, `AssetMode::Link { base_url: "/vendor" }` и `remote_images: false`. Для явно открытого файла без известного расширения используется Markdown по примеру README ядра. Сохраняются правила BOM, переносов и лимита ядра, включая баннеры. В случае отказа чтения вывести причину, имя файла и предложение закрыть окно и открыть файл снова.
- **FR-3.** Frontend разбирает полученный фрагмент через `DOMParser` и переносит полученный `main.nimmd` через `document.importNode`. Корневой контейнер сохраняет сообщения об ошибках открытия из оконного слоя и принимает существующее событие `nimmd-launch-changed`. Фрагмент имеет общую тему, стили подсветки и данных, системную светлую или тёмную схему, перенос длинных строк TXT. Доступны прокрутка, выделение и копирование текста. Сообщения загрузки и ошибок доступны со вспомогательными технологиями. Пример ошибки — «Не удалось прочитать „note.md“. Проверьте доступ к файлу, закройте окно и откройте его снова.»
- **FR-4.** После вставки запускать KaTeX только при наличии `[data-math-style]`, Mermaid только при наличии `pre.mermaid`. Подключать скрипты со своего origin по `/vendor/katex.min.js` и `/vendor/mermaid.min.js`, стили KaTeX по `/vendor/katex.min.css`; CSS использует шрифты из `/vendor/fonts`. KaTeX получает TeX из `textContent`, режим из атрибута, `trust: false` и `throwOnError: false`. Перед `mermaid.run` применять `securityLevel: 'strict'`, `startOnLoad: false` и тему документа. В сборке Mermaid настройки `layout: elk*` заменяются на `dagre` после разбора конфигурации. Просмотрщик передаёт исходный текст диаграммы без изменений. При ошибке или недоступности ресурса остальной документ остаётся читаемым, исходный блок сохраняется и пользователь видит, что не удалось отрисовать формулу или диаграмму. Загрузка библиотеки и повторные события оконных ошибок не дублируют содержимое и не сбрасывают чтение.
  Перед подготовкой и передачей блоков рендерерам проверить их исходный `textContent` в порядке документа. Длина формулы не превышает 4096 кодовых единиц UTF-16, диаграммы — 8192. На документ передавать обеим библиотекам суммарно не более 32 блоков и 32 768 кодовых единиц UTF-16. Для блока, превышающего любой предел, сохранить исходник и показать рядом причину пропуска. Такой блок не расходует общий лимит. Продолжить отрисовку следующих блоков, которые укладываются в остаток.

- **FR-5.** Устранить блокирующие записи RustSec в графе `nimmd-desktop`. Обновить `rustix` и `time`, заменить цепочку `plist → quick-xml` на версии с исправленным `quick-xml` и перейти на поддерживаемую цепочку Tauri для URL Pattern без затронутых `unic-*`. Подобрать совместимые опубликованные версии, зафиксировать их в lockfile и, если нужно для совместимости Tauri, согласованно обновить JS API и CLI. Сохранить политику `deny.toml` и полный граф для `cargo deny check`. Если исправленный граф требует нового MSRV, поднять до 1.90 только `nimmd-desktop`. Сохранить объявленный Rust 1.85 у workspace, `nimmd-core` и `nimmd-assets` и не повышать требования к Rust в их графах зависимостей.

### Привязка файла и предел чтения

Для FR-2 при регистрации окна зафиксировать идентичность выбранного обычного файла. Сохранить поддержку символьной ссылки при первом открытии и её имя в заголовке. Перед чтением проверить, что выбранный путь по-прежнему обозначает зарегистрированный файл. Проверку типа и идентичности фактически открытого объекта выполнять на том же дескрипторе, из которого читаются байты. Исчезновение, потеря доступа или замена объекта приводят к сообщению FR-2 в этом окне. Открытие и проверка типа специального объекта завершаются без ожидания данных из него.

Хост читает и декодирует ограниченный префикс. Объём чтения, включая проверочное, не превышает `2 * text::MAX_BYTES + 8` сырых байт. Запас нужен для BOM, возможного удвоения длины из-за CRLF и завершения символа около границы. Видимый префикс и баннер обрезки соответствуют лимиту ядра после удаления BOM и нормализации переносов. Баннер невалидного UTF-8 относится к прочитанному префиксу. Искусственно неполный символ на границе чтения не считается ошибкой кодировки. Неполная последовательность в действительном конце файла считается невалидной.

### Сценарии для пограничных состояний

- **AC-1.** Для одного пути проверить оба порядка запуска. Сначала `--view`, затем CLI без флага. В отдельном запуске сначала без флага, затем `--view`. В каждом случае уже созданное окно получает фокус, остаётся единственным для файла и сохраняет исходную страницу и режим.
- **AC-1.** Открыть один и тот же CSV через CLI без `--view`, через «Открыть в программе» в Finder и перетаскиванием на пустое окно NimMD. Перед каждым открытием убедиться, что для этого файла ещё нет окна. Во всех трёх случаях новое окно показывает заголовок «Редактирование» и путь к CSV в текущем каркасе (`Mode::Edit`). После закрытия файлового окна открыть тот же CSV через `nimmd --view` и проверить, что новое окно показывает цветные столбцы в `Mode::View`.
- **AC-1, AC-3.** Тестовым барьером приостановить фоновое чтение после регистрации окна. До снятия задержки проверить видимое сообщение загрузки со статусной семантикой и работу второго окна. После снятия задержки содержимое первого окна заменяет статус. Вариант с отказом показывает доступное сообщение с именем файла и способом повторить открытие.
- **AC-2.** Сверить объём прочитанных байтов с пределом FR-2 на большом файле с BOM, частыми CRLF и многобайтовым символом на границе нормализованного префикса. Сравнить видимый префикс с выводом ядра для полного тестового содержимого. Должны быть баннер обрезки и целые символы до границы. Подготовить два файла с одинаковыми первыми `2 * text::MAX_BYTES + 8` байтами. Общий префикс заканчивается началом многобайтового символа. Первый файл заканчивается на этой границе, и окно показывает баннер невалидного UTF-8. Во втором файле оставшиеся байты завершают символ за границей, и баннер отсутствует. Для обоих файлов подтвердить соблюдение предела чтения с учётом проверочных байтов. Для неполной последовательности в действительном конце небольшого файла также проверить наличие баннера.
- **AC-3, AC-5.** Открыть обычный файл через символьную ссылку и проверить исходное имя и содержимое. В отдельных тестах после регистрации удалить выбранный файл, запретить чтение непривилегированному процессу, заменить обычный файл другим или изменить цель ссылки. Чтение отвечает видимым отказом без показа содержимого другого файла. Если в проверку попал специальный объект, отказ приходит без ожидания его данных. После отказа закрыть проблемное окно, восстановить исходный файл или доступ и повторить ту же команду. Новое окно показывает правильное содержимое. Если реализация отдельно проверяет путь до открытия файла, установить тестовый барьер сразу после успешной проверки пути и до открытия дескриптора. В отдельных тестах заменить объект по этому пути на другой обычный файл с отличимым содержимым и на специальный объект без данных. После снятия барьера в обоих случаях окно показывает сообщение FR-2. Содержимое другого файла не появляется. Для специального объекта подтвердить отказ в пределах тайм-аута теста без подачи ему данных.
- **AC-4.** Проверить блок Mermaid с настройкой `config.layout: elk` во frontmatter диаграммы и подписью узла `A["layout: elk"]`. В разобранной конфигурации Mermaid выбирается `dagre`, а исходный текст, включая подпись, передаётся побайтово. Диаграмма отрисовывается через dagre, и в SVG видна подпись `layout: elk`.
- **AC-4.** Для каждой библиотеки отдельно проверить отсутствие ресурса и ошибку синтаксиса блока. В каждом случае исходник проблемного блока остаётся читаемым, появляется сообщение о сбое, соседний корректный блок другой библиотеки отрисовывается, остальной документ доступен. При ошибке синтаксиса соседний корректный блок той же библиотеки также отрисовывается.
- **AC-4, AC-5.** Для синтаксически корректных блоков проверить точные границы длины формулы и диаграммы и превышение на одну кодовую единицу. Отдельно проверить достижение и превышение общих пределов по количеству блоков и длине текста в документах с KaTeX и Mermaid. Проверить, что рендереры не получают пропущенные блоки, их исходник и причина пропуска видны, уже отрисованный документ читается, а следующий корректный блок отрисовывается, если укладывается в остаток.
- **AC-6.** Проверить запросы на документе с одной формулой и на отдельном документе с одной диаграммой. Первый загружает только ресурсы KaTeX, второй только Mermaid. Адреса принадлежат origin страницы просмотра.

## Границы, точки входа и проверки

- `app/mod.rs` регистрирует команду вместе с `get_launch`. Объявить её в build manifest и выдать узкое разрешение в capability. `app/windows.rs` выбирает страницу по уже зарегистрированному режиму, данные берутся по метке окна. Нет параметров пути/метки от WebView, доступа к сторонним файлам по ссылкам, новых плагинов или разрешений общего назначения. CLI по-прежнему подтверждает открытие окна. Ошибка чтения отображается в самом окне. Повторное фокусирование не меняет режим ранее открытого файла.
- Для холодного запуска `--view` подготовить привязку файла в фоновом исполнителе. При тёплом запуске подготовить привязку на существующем потоке CLI IPC в `app/cli.rs` до передачи запроса главному потоку. Подготовка включает канонизацию пути, проверку типа файла и фиксацию его идентичности по FR-2. Создание или активация окна остаётся в главном потоке. Тёплый CLI получает результат после завершения оконной операции и активации приложения, как в #52. Чтение и рендер документа для ответа Tauri-команды выполняются отдельно.
- Переиспользовать ядро как локальную зависимость `nimmd-core`, CSS `packages/theme/{nimmd,highlight,data}.css`, сценарий оконных ошибок и закреплённый Vite. `Rendered.body` содержит только `main`. `Link` применяется ядром в `head`, поэтому просмотрщик сам подгружает статические файлы и вызывает библиотеки после вставки. Скрипты загружаются только из известных путей приложения. Навигация просмотрщика ограничена своей страницей и её якорями. Сохранить CSP и API ядра.
- На 2026-11-19 манифесты и lockfile закрепляют Tauri 2.11.6, tauri-build 2.6.3, Tauri JS 2.11.1 и CLI 2.11.5, Vite 8.3.7, KaTeX 0.19.1, Mermaid 12.2.0. MSRV 1.85, Node ≥26, pnpm для проекта 12.18.0, macOS ≥14. В среде выполнены `rustup run stable rustc -V`, `node -v`, `pnpm -v`, `sw_vers`. Установлены Rust 1.99.1, Node 26.13.1, pnpm 12.21.0, macOS 27.2.1. Текущий `comrak 0.56.0` уже заявляет Rust 1.89, а `criterion 0.8.2` из dev-графа ядра — Rust 1.86. AC-8 проверяет сохранение декларации и отсутствие ухудшения относительно исходного графа. Восстановление фактической сборки ядра на 1.85 находится за пределами задачи. Локальный исходник Tauri 2.11.6 `src/webview/webview_window.rs` подтверждает `WebviewWindowBuilder::from_config` и `on_navigation`. Имена глобальных скриптов и состав файлов подтверждают `packages/vendor/fetch.sh`, `build-mermaid.mjs`, `check-mermaid.mjs` и текущие `packages/theme/*-init.js`. Эти версии образуют точку сравнения для FR-5.
- В исходном `Cargo.lock` зафиксированы `rustix 1.1.5`, `time 0.3.45`, `quick-xml 0.38.4` через `plist 1.8.0` и `unic-* 0.9.0` через `tauri-utils → urlpattern 0.3.0`. RustSec указывает исправления в `rustix ≥1.1.6`, `time ≥0.3.47` и `quick-xml ≥0.41.0`. Для затронутых `unic-*` исправленной версии нет. Сверять выбранные версии и их MSRV по манифестам опубликованных пакетов. Если совместимого исправленного графа в согласованных границах нет, приёмка AC-8 заблокирована.
- Риск высокий из-за импорта HTML в привилегированное окно и первой связи контента файла с IPC. Ранние архитектура, security, QA и UX проверяют границы Rust/WebView, загружаемые ресурсы и сценарии отчёта об ошибке. Тесты Rust и Vitest покрывают изоляцию, типы файлов, DOM, условные загрузки и отрицательные сценарии. Для существенных изменений сначала проверить RED.
