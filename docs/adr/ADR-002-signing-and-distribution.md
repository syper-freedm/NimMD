# ADR-002: Подпись и распространение v1

**Status:** Accepted (2026-10-24, автор проекта)
**Date:** 2026-10-23
**Deciders:** автор проекта

## Context

Спека (раздел 4, «Подпись») оставила открытым выбор: v1 только для личного
использования с ad-hoc подписью, или v1 для распространения с Developer ID и
нотаризацией. Силы:

- macOS 15+ не открывает скачанное из браузера приложение без Developer ID
  и нотаризации иначе как через «Системные настройки → Всё равно открыть»;
  Quick Look-расширение в карантинном `.app` может не зарегистрироваться;
- Quick Look игнорирует неподписанные расширения, но ad-hoc подписи
  достаточно;
- требование «ноль внешних зависимостей при установке» касается
  пользователя, который скачивает `.dmg`, а не разработчика, который
  собирает локально;
- Developer ID — платная подписка Apple Developer и секреты в CI;
- автообновление (спека 5.6) проверяет артефакт подписью minisign, а не
  подписью Apple. Файлы, которые приложение скачивает само, не получают
  атрибута карантина, поэтому Gatekeeper обновлённый бандл не проверяет.

Спека ставила «автообновление переносится на следующий этап» в один пакет
с ad-hoc подписью. Это не обязательная связка: нотаризация нужна только для
первой установки чужим пользователем.

## Decision

v1 собирается и подписывается ad-hoc. Первая установка — локальная сборка
(на другой Mac — через «Всё равно открыть»); дальнейшие версии приложение
получает само из GitHub Releases через автообновление (этап 8) с подписью
minisign. В v1 публикуется только macOS-артефакт и `latest.json` с одной
платформой (спека 5.6, 9). CI пишется так, что Developer ID и нотаризация
включаются добавлением секретов, без правки пайплайна.

## Options Considered

### Option A: ad-hoc, без автообновления

| Dimension | Assessment |
|-----------|------------|
| Complexity | Low |
| Cost | 0 |
| Scalability | Один пользователь — автор |
| Team familiarity | Высокая |

**Pros:** ничего лишнего в v1.
**Cons:** этап 8 откладывается без необходимости; обновлять Quick Look-плагин
придётся пересборкой вручную.

### Option B: Developer ID + нотаризация в v1

| Dimension | Assessment |
|-----------|------------|
| Complexity | Med — сертификат, `notarytool`, секреты CI, stapler |
| Cost | Подписка Apple Developer, ежегодно |
| Scalability | Любой пользователь, скачивание из браузера |
| Team familiarity | Средняя; `tauri-action` умеет это из коробки |

**Pros:** можно дать ссылку кому угодно; TCC-разрешения и подпись стабильны
между сборками.
**Cons:** деньги и настройка ради v1, у которого пока нет внешних
пользователей; блокирует этап 7 до получения сертификата.

### Option C: ad-hoc, автообновление остаётся, CI готов к Developer ID (выбрано)

| Dimension | Assessment |
|-----------|------------|
| Complexity | Low–Med — пайплайн пишется один раз с условными шагами |
| Cost | 0 сейчас; подписка — когда появится внешний пользователь |
| Scalability | Автор сейчас; переход к B без изменений кода |
| Team familiarity | Высокая |

**Pros:** этап 8 не откладывается; Quick Look-плагин обновляется с
приложением; переход к распространению — добавить секреты.
**Cons:** ad-hoc подпись у каждой сборки своя: после обновления macOS
сбросит TCC-разрешения приложения (у NimMD их нет); первая установка на
другой Mac — только через «Всё равно открыть».

## Trade-off Analysis

A и C равны по стоимости, но C сохраняет этап 8 и путь обновления
Quick Look-плагина, который иначе пришлось бы проверять заново позже. B
покупает дистрибуцию, которой в v1 нет кому пользоваться; её можно
включить позже без переделки, если CI с самого начала умеет оба режима.

Риск C: нужно подтвердить, что `tauri-plugin-updater` на macOS 15+
запускает обновлённый ad-hoc бандл без диалога Gatekeeper и что система
перерегистрирует appex после замены. Это входит в тест этапа 8.

## Consequences

- Проще: этап 7 не ждёт сертификата; выпуск по тегу появляется на этапе 8
  и не зависит от Apple (К19).
- Сложнее: пайплайн содержит условные шаги подписи и нотаризации, которые
  до появления секретов не выполняются и не проверяются.
- Пересмотреть: при первом внешнем пользователе — купить подписку, добавить
  секреты, перевести ADR в Superseded записью о Developer ID.
