# ADR-001: Ядро решает, можно ли править файл в WYSIWYG

**Status:** Superseded by `ADR-004-editor-engine.md` (2026-10-24)
**Date:** 2026-10-23
**Deciders:** автор проекта

> Решение отменено: редактор строится на CodeMirror 6 с моделью «текст»
> (ADR-004), файл никогда не сериализуется из дерева, и арбитр сохранности
> не нужен. Текст ниже сохранён как история рассуждений.

## Context

Анти-цель 1 спеки (`docs/superpowers/specs/2026-10-19-nimmd-design.md`)
запрещает молча терять содержимое. Milkdown и remark не знают синтаксис
Obsidian и MultiMarkdown: при круговом проходе `[[link]]` превращается в
`\[\[link]]`, портятся `%%…%%` и `{#id}`. Формально текст на месте, но для
Obsidian файл сломан.

Прежняя защита — баннер «разметка будет приведена к единому стилю», который
показывается, если `stringify(parse(src)) != src`. Это условие выполняется
почти для любого реального файла, поэтому баннер превращается в шум, а
настоящую порчу разметки не предотвращает.

## Decision

`roundtrip(x)` — полный проход редактора, вызванный из JS: Markdown →
документ ProseMirror → Markdown. Голые `remark.parse` + `stringify` не
подходят: содержимое теряется в схеме ProseMirror (неизвестные узлы,
`html`-узлы, сноски без плагина), и remark этого не покажет. Ядро
сравнивает AST comrak у двух текстов; разница в стиле не учитывается:
маркеры списков, `*`/`_`, выравнивание таблиц. Экранирование считается
стилем только внутри конструкций, которые comrak разобрал (ссылка,
эмфаза, код). Добавленный `\` внутри обычного текстового узла — это
расхождение: для comrak `%%a [b]%%` и `{#id}` — просто текст, и иначе
порча этих конструкций проходила бы проверку, хотя именно она названа
мотивом в Context (ревью 2026-10-24, Р16). По готовому AST это не видно:
comrak разрешает экранирование при разборе, и текстовые узлы у `[b]` и
`\[b]` одинаковы. Поэтому ядро включает `escaped_char_spans` и сравнивает
узлы `NodeValue::Escaped` как часть AST (К5); если в выбранной версии
comrak опции нет — сравниваются исходные срезы текстовых узлов по
`sourcepos`. Белый список допустимых экранирований в тексте — явный и
покрыт фикстурами.

Сравнение выполняется над телом после `split_frontmatter`, без BOM, с
переносами, нормализованными к `\n` (Р28).

Три инварианта (Б1, уточнены по ревью 2026-10-24, Р1–Р3). Все три
касаются только WYSIWYG: в режиме исходника текст `<textarea>` пишется как
есть, иначе файлы Obsidian и MultiMarkdown, у которых круговой проход
проваливается по определению, нельзя было бы сохранить (Р2).

- **При открытии — представимость:** `AST(src) ≡ AST(roundtrip(src))`.
  - Совпали — файл открывается в WYSIWYG. Баннер «стиль будет
    нормализован» показывается, только если текст действительно изменится.
  - Не совпали — по умолчанию открывается режим исходника. WYSIWYG
    включается явным переключением, и перед этим показывается
    предупреждение со списком того, что изменится. Та же проверка
    повторяется над текущим текстом `<textarea>` при переключении Cmd+/ в
    WYSIWYG.
- **Перед записью — верность:** `parse(candidate)` эквивалентен текущему
  документу ProseMirror, где `candidate` — текст, который сериализатор
  выдал из этого документа. Это ловит потерю на шаге «документ → текст»:
  если сериализатор выбросил узел, в `candidate` его нет, а в документе
  есть. Объект «src плюс правка» существует — это текущий документ
  ProseMirror; с `src` сравнивать бессмысленно, после правки они
  различаются по определению (Р1). Эквивалентность — не `Node.eq` (К1):
  он сравнивает attrs строго, а у Milkdown есть производные атрибуты (`id`
  заголовка, `label`, `listType`, `spread`), и пустой абзац после Enter
  remark не сохраняет — обычный набор давал бы ложные провалы.
  Сравниваются `doc.toJSON()` обоих документов после нормализации по
  явному списку игнорируемых атрибутов и узлов; каждая строка списка
  покрыта фикстурой, которая без неё падает.
- **Перед записью — идемпотентность:**
  `AST(candidate) ≡ AST(roundtrip(candidate))` через comrak. Это страховка
  от недетерминизма сериализатора, а не независимая проверка (К9): при
  детерминированном сериализаторе из верности следует
  `roundtrip(candidate) = candidate` текстуально, и инвариант проходит
  тривиально. Независимая проверка comrak действует при открытии;
  содержимое перед записью защищает верность.

**Провал перед записью (Р3, К-Р3):** запись не выполняется, автосохранение
приостанавливается, файл на диске не трогается. `candidate` — текст с
потерей, поэтому баннер показывает список потерянного и предлагает:
«открыть как исходник» — в `<textarea>` попадает `candidate`, список
потерь остаётся над ним, и запись из исходника — осознанный шаг после
этого списка; «сохранить копию» — рядом пишутся
`<имя>.nimmd-recovery-<отметка времени>[-N].md` (`candidate`) и такой же
`.json` (`doc.toJSON()`, без потерь), с правами `0600`, старые копии не
перезаписываются; если каталог документа недоступен для записи, копия
уходит в каталог данных приложения (`tauri::path::app_data_dir`), и баннер
называет путь; редактор остаётся в WYSIWYG с остановленным
автосохранением. До выбора правки живут в редакторе; закрытие окна, Cmd+Q
и перезапуск по обновлению в этом состоянии показывают вопрос по общему
правилу спеки 5.4 (Ч1, П1): окно закрывается только после успешной
записи, провал проверки в момент закрытия тоже ведёт к вопросу.

**Где выполняется (К7):** проверки — в Web Worker. `EditorView` там не
создать (нет DOM), поэтому `roundtrip` собирается из схемы и
remark-плагинов через `@milkdown/transformer`
(`ParserState`/`SerializerState`); документ передаётся как `doc.toJSON()`
и пересобирается по той же схеме.

## Options Considered

### Option A: только баннер (как в исходной спеке)

| Dimension | Assessment |
|-----------|------------|
| Complexity | Low |
| Cost | Почти ноль |
| Защита от потери | Нет |
| Шум для пользователя | Баннер почти на каждом файле |

**Pros:** ничего не надо писать.
**Cons:** анти-цель 1 не выполняется; пользователь привыкает закрывать баннер.

### Option B: арбитр в ядре (выбрано)

| Dimension | Assessment |
|-----------|------------|
| Complexity | Med — приведение AST к нормальной форме, список допустимых расхождений |
| Cost | Проход comrak при открытии и сохранении — на 1 МБ около 10–30 мс; главная стоимость — `roundtrip` на стороне JS (разбор и сериализация всего документа Milkdown, на 1 МБ сотни миллисекунд) и передача `candidate` в Rust перед каждым автосохранением (Р23). Мера: проверки в Web Worker, `candidate` уходит в Rust один раз — на проверку и на запись; при паузах на 1 МБ растёт задержка автосохранения, проверка не отключается |
| Защита от потери | Да, механическая и покрытая тестами |
| Шум для пользователя | Только когда есть реальный риск |

**Pros:** гарантию можно проверить; comrak — независимый от remark парсер,
поэтому ошибки одного не маскируются ошибками другого; не нужно писать
парсеры диалектов.
**Cons:** у файлов Obsidian и MultiMarkdown в v1 по умолчанию режим исходника.

### Option C: свои Milkdown-плагины под каждый диалект

| Dimension | Assessment |
|-----------|------------|
| Complexity | High |
| Cost | Плагин и сериализатор на каждую конструкцию |
| Защита от потери | Частичная, растёт по мере покрытия |
| Шум для пользователя | Низкий |

**Pros:** полноценный WYSIWYG для Obsidian и MultiMarkdown.
**Cons:** объём работы не для v1; без арбитра каждая непокрытая конструкция
снова означает тихую порчу.

## Trade-off Analysis

B даёт гарантию, проверяемую тестом, ценой того, что часть файлов в v1
открывается как исходник. C понадобится для полноценного Obsidian, но и после
этого B остаётся страховкой: каждая новая конструкция, которую плагины ещё не
знают, ловится арбитром, а не пользователем.

## Consequences

- Проще: анти-цель 1 закрыта тестом, а не надеждой; баннер о нормализации
  появляется только по делу.
- Сложнее: нужно приведение AST к нормальной форме и явный список допустимых
  расхождений; при каждом открытии и сохранении — лишний проход парсера.
- Пересмотреть: когда появится вариант C, сузить круг файлов, которые
  открываются как исходник.

## Action Items

1. [ ] `nimmd-core`: `fn ast_equivalent(a: &str, b: &str) -> Result<(), Vec<Diff>>`;
       редактор вызывает её с парами `(src, roundtrip(src))` при открытии и
       `(candidate, roundtrip(candidate))` перед записью. Добавленный `\` в
       текстовом узле — расхождение, кроме явного белого списка.
2. [ ] Фикстуры для каждого диалекта с ожидаемым результатом safe/unsafe,
       среди них `%%a [b]%%` и `{#id}` (unsafe при экранировании).
3. [ ] Тест идемпотентности на подменённом сериализаторе, который на каждом
       втором вызове меняет AST (выбрасывает или дублирует узел): проходит
       верность, падает на идемпотентности (спека 8, Т2). Стилевой
       недетерминизм (`*`/`_`) для этого не годится — AST comrak одинаков.
4. [ ] Редактор: `roundtrip` через `@milkdown/transformer` в Web Worker, а
       не через remark напрямую и не через `EditorView`; проверка верности
       — нормализованное сравнение `doc.toJSON()` со списком игнорируемого
       и фикстурой на каждую строку списка; выбор режима при открытии и
       при Cmd+/; запись из режима исходника без проверок; при провале —
       остановка автосохранения, баннер со списком потерь и действиями
       «открыть как исходник / сохранить копию» (`.md` + `.json`),
       подтверждение при закрытии окна, Cmd+Q и перезапуске по обновлению.
5. [ ] Сквозной тест (К10): Vitest пишет `<имя>.roundtrip.md` рядом с
       фикстурами, `cargo test` сравнивает пары через `ast_equivalent`, CI
       проверяет, что файлы не устарели.
