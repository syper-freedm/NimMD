# Ручные проверки NimMD

## В7. Холодный запуск `--view` на Apple Silicon

Проверка [№55](https://github.com/syper-freedm/NimMD/issues/55) от 20 ноября 2026 года.
MacBook Pro с Apple M3 Pro и 18 ГБ памяти, macOS 27.2.1 (26B131), дисплей 60 Гц,
питание от сети. Вход — [GFM-фикстура](../crates/nimmd-core/tests/fixtures/gfm/table_tasks.md)
с таблицей, флажками и зачёркиванием (62 байта).

Проверены два релизных бандла `NimMD.app` 0.1.0 из одной базы
`7e08c4a1b9bf2ec560432d86447cb063f9df9d6c`: чистый `main` и отдельная
копия с локальными изменениями [№54](https://github.com/syper-freedm/NimMD/issues/54).
На момент замера изменения №54 ещё были вне `main`. SHA-256 манифеста из
212 исходных файлов снимка — `861abc89d77708796d726be5c73a9c17b45a8872c8fa53d6230938b564781485`.

### Методика

1. Установить зависимости через `pnpm -C apps/desktop install --frozen-lockfile`
   и собрать приложение через `pnpm -C apps/desktop tauri build --bundles app`.
   Использованы Rust 1.99.1, Node.js 26.13.1 и pnpm 12.18.0 для приложения.
2. В разблокированном сеансе macOS с разрешённым захватом экрана начать
   поток ScreenCaptureKit для основного дисплея. Исключить приложения,
   открытые перед калибровкой. Сохранять из кадров область 235 × 210 пикселей
   окна NimMD (на стенде — 1 пиксель захвата на точку, смещение 96 точек
   вправо и 48 вниз от левого верхнего угла окна). На калибровочном запуске
   подтвердить, что в области видны ячейки таблицы, флажки и зачёркнутый текст.
3. Для каждой сборки выполнить 10 запусков через
   `NimMD.app/Contents/MacOS/nimmd --view <абсолютный путь к фикстуре>`.
   В каждом прогоне создаётся новый процесс, после его завершения пауза
   около 1 с. Кэши macOS сохраняются между запусками.
4. Из `SCStreamFrameInfo.displayTime` первого захваченного кадра, где
   одновременно видны все три признака форматирования, вычесть метку
   `mach_absolute_time()`, взятую перед `posix_spawn`. Захват продолжается
   до первого попиксельного совпадения с калибровочным кадром. Чтобы выбрать
   первый отформатированный кадр, сохранить все уникальные области в BGRA
   и сопоставить их с метками времени каждого кадра. Таблица показывает
   время первого визуально подтверждённого кадра с документом.
5. В каждой серии отдельно проверить фон без NimMD и показ тех же байтов
   как `.txt`. Оба контроля отличались от отформатированного Markdown.

### Результат

Цель **менее 500 мс** выполнена в обеих сериях, по **10 из 10** прогонов.
Для сборки со снимком №54 медиана **456,2 мс**, максимум **475,4 мс**.
Для чистого `main` медиана **455,4 мс**, максимум **472,7 мс**.

| ---: | ---: | ---: |
| 1 | 444,8 | 462,6 |
| 2 | 457,9 | 475,4 |
| 3 | 458,7 | 440,6 |

Во всех прогонах предыдущий захваченный кадр был пустым или показывал статус
загрузки, а интервал до кадра с документом составлял около 16,7 мс.
Результат относится к прямому CLI-запуску на этой машине и компактной
GFM-фикстуре. Открытие из Finder, первый запуск после перезагрузки и документы
с картинками, формулами или диаграммами в эту проверку не входили.

## Приёмка выпуска macOS

Для каждого прогона запишите версию NimMD, версию macOS, архитектуру и SHA-256
образа. Напротив каждого шага укажите результат или причину пропуска.
Хеш образа можно получить командой `shasum -a 256 NimMD.dmg`.

### Сборка и артефакты

1. Выполните `just build-macos` по [инструкции сборки](../README.md#сборка-из-исходников).
   В каталоге `target/macos-release/<rust-target>/` должны появиться `NimMD.app`,
   `NimMD.app.tar.gz`, `NimMD.app.tar.gz.sig` и `NimMD.dmg`.
2. Из каталога артефактов проверьте подписи приложения и расширения, распакуйте архив
   и сравните его содержимое с исходным бандлом.

   ```sh
   check=$(mktemp -d)
   codesign --verify --deep --strict NimMD.app
   codesign --verify --strict NimMD.app/Contents/PlugIns/NimMDQuickLook.appex
   test -s NimMD.app/Contents/Resources/THIRD_PARTY_LICENSES.html
   test -s NimMD.app/Contents/Resources/RUST_STDLIB_COPYRIGHT.html
   tar -xzf NimMD.app.tar.gz -C "$check"
   diff -qr NimMD.app "$check/NimMD.app"
   ```

3. Проверьте подпись архива с помощью Minisign. Укажите абсолютный путь к открытому
   ключу `.pub`, созданному Tauri вместе с ключом, которым подписан именно этот архив.
   Tauri кодирует открытый ключ и подпись в Base64.

   ```sh
   base64 -D -i /абсолютный/путь/updater.key.pub -o "$check/updater.pub"
   base64 -D -i NimMD.app.tar.gz.sig -o "$check/NimMD.app.tar.gz.minisig"
   minisign -Vm NimMD.app.tar.gz -p "$check/updater.pub" -x "$check/NimMD.app.tar.gz.minisig"
   ```

4. Выполните `hdiutil verify NimMD.dmg`, откройте образ в Finder и проверьте,
   что в нём есть `NimMD.app` и ссылка на «Программы». Повторите проверку
   `codesign --verify --deep --strict` на бандле в смонтированном образе и
   сравните его с исходным `NimMD.app` через `diff -qr`.

### Установка на чистой macOS

1. Загрузите `NimMD.dmg` браузером на чистой ВМ macOS 14 или новее без
   предыдущей версии NimMD, Xcode, Rust и Node.js. Используйте артефакт для
   архитектуры ВМ. Перетащите приложение в «Программы», извлеките образ
   и запустите установленный NimMD.
2. Если Gatekeeper заблокировал первый запуск доверенного бандла с ad-hoc
   подписью, выполните шаг «Все равно открыть» из
   [инструкции установки](../README.md#установка). Запишите, появился ли запрос
   Gatekeeper. После подтверждения приложение должно открыться из «Программ»,
   а после выхода через ⌘Q успешно запуститься повторно.
3. Откройте тестовый `.md` в NimMD и проверьте, что он доступен для редактирования.
   В меню «NimMD → О NimMD → Лицензии» должен открыться локальный HTML с
   уведомлениями о сторонних компонентах.

### Quick Look в Finder

1. Нажмите пробел на [Markdown с таблицей и флажками](../crates/nimmd-core/tests/fixtures/gfm/table_tasks.md).
   Должны появиться отформатированные таблица, флажки и зачёркивание. Повторите,
   сохранив копии с расширениями `.markdown`, `.mdown` и `.mkd`.
2. Проверьте `.toml`, `.yaml`, `.yml`, `.json` и `.csv` с несколькими строками.
   TOML, YAML и JSON должны открываться с подсветкой, столбцы CSV — выделяться цветом.
   Для `.txt` должен открываться системный просмотр текста.
3. Положите PNG рядом с тестовым `.md` и добавьте в документ ссылки
   `![Локальная](fixture.png)`, `![Внешняя](../outside.png)` и
   `![Удалённая](https://example.invalid/fixture.png)`. Положите вторую PNG
   в родительский каталог. Проверьте, что видна картинка из каталога документа и две
   остальные не загружаются. Проверьте формулу KaTeX и диаграмму Mermaid
   с отключённой сетью.
4. Откройте одну и ту же Markdown-фикстуру в светлом и тёмном оформлении macOS.
   Фон и текст превью должны переключиться вместе с оформлением системы.
5. Назначьте NimMD приложением по умолчанию для `.md` по
   [инструкции](../README.md#nimmd-по-умолчанию-для-md). Снова нажмите пробел
   на `.md`. Кнопка «Открыть в NimMD» должна открыть тот же документ в редакторе.

### Сохранение на exFAT и SMB

1. Создайте локальные образцы с UTF-8 BOM и переносами CRLF во временном каталоге.

   ```sh
   check=$(mktemp -d)
   printf '\357\273\277# NimMD\r\n' > "$check/original.md"
   printf '\357\273\277# NimMD\r\nSaved\r\n' > "$check/expected.md"
   ```

2. На каждом из двух томов скопируйте `original.md` в отдельную тестовую папку.
   В NimMD добавьте в конец файла строку `Saved` с переносом и нажмите ⌘S.
   Откройте файл повторно и проверьте, что строка сохранилась. Сравните файл
   с `expected.md` командой `cmp`. Совпадение подтверждает сохранность BOM и CRLF.
3. На отдельной тестовой копии отключите запись на стороне носителя или сервера.
   Внесите правку в NimMD и попробуйте сохранить её. Должно появиться сообщение
   об ошибке, исходный файл должен сохраниться без изменений. Нажмите
   «Сохранить копию» и проверьте черновик по указанному приложением пути.
