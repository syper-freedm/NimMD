# Журнал делегированных решений: #42 «Завендорить KaTeX и Mermaid без elkjs»

## 2026-10-25 12:30 — блок вопросов начального обсуждения (шаг 1): замена elk→dagre, менеджер пакетов, место гейта elkjs, состав dist

- **Вопрос:** (1) где живёт замена `layout: elk*` → dagre — в хостах (#43/#53, как в спеке 5.4 и плане Task 4), в обёртке над `mermaid.run/render` внутри бандла, или через подмену elk-раскладки на dagre при сборке; (2) менеджер пакетов `packages/vendor` — `npm ci` + `package-lock.json` (план Task 6) или pnpm + `pnpm-lock.yaml` + override `elkjs: "-"`; (3) где гейт «сборка падает, если elkjs попал в бандл» — только в `just vendor` или ещё и в `just lint`/CI; (4) состав `dist/` — ровно «Produces» Task 6 или плюс auto-render/contrib KaTeX.
- **Варианты:**
  - (1а) только заглушка ELK + проверки бандла в #42; регулярка остаётся в #43 (инлайн-скрипт ядра) и #53 (фронтенд `--view`); фикстуры `features/mermaid.md`, `features/mermaid_elk.md` и шаг 5 Task 6 (ручная проверка рендера) переезжают в #43. Цена: ноль нового кода в #42; одна строка-регулярка повторяется в двух хостах — так уже записано в спеке.
  - (1б) обёртка над `mermaid.run`/`mermaid.render` в `mermaid-entry.js`. Цена: монки-патч публичного API стороннего пакета (несколько точек входа и форм аргументов `run`), DOM-мутации нашего кода в каталоге, который исключён из semgrep-правил по DOM (`/packages/vendor/**` в `.semgrep.yml`); бандл перестаёт быть «апстрим минус elkjs».
  - (1в) перерегистрация имён `elk*` на загрузчик dagre подменой внутреннего модуля mermaid при сборке. Цена: зависимость от внутренних путей чанков mermaid (хэшированные имена в dist), публичного API для этого нет; работоспособность на 12.2.0 не проверена.
  - (2а) `npm ci` + `package-lock.json`. Цена: `just npm-licenses` (`pnpm licenses list`) и проверка `pnpm why elkjs` из спеки не работают без pnpm-раскладки; в стеке проекта менеджер — pnpm.
  - (2б) pnpm + `pnpm-lock.yaml` + override `elkjs: "-"`. Цена: один файл настроек; elkjs вообще не ставится — `pnpm why elkjs` пуст, лицензионный гейт проходит без исключений для EPL-2.0.
  - (2в) pnpm без override + исключение для elkjs в скрипте лицензий. Цена: новая ветка в `check-npm-licenses.mjs` и ослабление гейта ради devDependency.
  - (3а) гейт только в `just vendor`. Цена: ручной запуск — обновление mermaid, протащившее elkjs, заметят не раньше следующего ручного `just vendor`; при этом `just npm-licenses` всё равно требует установленных зависимостей, иначе падает и локально, и в CI.
  - (3б) `just vendor` = установка (frozen lockfile) + копирование KaTeX + сборка mermaid с проверкой metafile + `check-mermaid.mjs`; `just lint` зависит от `vendor`; job `lint` в CI получает pnpm (pinned action). Цена: pnpm становится обязательным для `just lint` (он уже обязателен из-за `npm-licenses`), плюс несколько секунд esbuild на каждый lint.
  - (4а) ровно «Produces» Task 6: `katex.min.css`, `katex.min.js`, `fonts/` целиком, `mermaid.min.js` + `mermaid.min.js.LEGAL.txt`. Цена: ноль сверх плана.
  - (4б) плюс `contrib/` KaTeX (auto-render, mhchem, copy-tex). Цена: лишние файлы в бандле; спека 5.4 прямо говорит, что auto-render не годится (comrak отдаёт TeX без `$`); остальное никто не просил.
- **Решение:**
  1. **(1а).** В #42 — заглушка `elk-stub.js`, плагин esbuild, проверка metafile и `check-mermaid.mjs`. Замена `layout: elk*` → dagre реализуется там, где живёт код рендера: #43 (инлайн-скрипт ядра, Task 4) и #53 (фронтенд `--view`), как зафиксировано спекой 5.4 и планом Task 6 («такие диаграммы скрипт из Task 4 переводит на dagre»). Фикстуры `features/mermaid.md`, `features/mermaid_elk.md` и шаг 5 Task 6 переносятся в #43. В #42 контракт фиксируется одной строкой в `packages/vendor` (комментарий в `elk-stub.js`/`build-mermaid.mjs`): бандл без ELK, хост обязан переписать `layout: elk*` → dagre до вызова mermaid. Пункт чек-листа issue «замена `layout: elk*` → dagre» оркестратор отмечает ссылкой на #43/#53, а не как выполненный в #42.
  2. **(2б).** pnpm, `pnpm-lock.yaml`, `pnpm install --frozen-lockfile` в `fetch.sh`; override `elkjs: "-"` там, где его читает pnpm 12 (по спайку — `pnpm-workspace.yaml` внутри `packages/vendor`; `packages/vendor` — самостоятельный пакет со своим lockfile, корневой workspace не заводится — `apps/desktop` по стеку тоже со своим `pnpm-lock.yaml`). Заглушка elkjs в esbuild остаётся (импорт должен резолвиться при сборке). Те же соглашения, что у фронтенда в стеке: `.npmrc` с `ignore-scripts=true`. Проверка уязвимостей для vendor в стеке должна стать `pnpm -C packages/vendor audit` вместо `npm audit --prefix` — правка конфигурации стека за оркестратором.
  3. **(3б).** Гейт в `just vendor` (metafile + `check-mermaid.mjs` внутри рецепта, отдельного ручного вызова не нужно), `just lint` получает `vendor` в зависимости, job `lint` CI ставит pnpm (pinned по SHA, как остальные actions). Job `test` не трогается.
  4. **(4а).** Ровно «Produces» Task 6 плюс `mermaid.min.js.LEGAL.txt` (побочный продукт `legalComments: "external"`). Никакого `contrib/`, `fonts/` не прореживается.
- **Обоснование:**
  - Уровень 1: (1б) и (1в) — не костыли по букве, но (1в) опирается на непроверяемые внутренние пути чанков, а (1б) прячет наш DOM-код в каталог, исключённый из линтеров проекта; оба делают вендорный бандл модифицированным апстримом. (2в) ослабляет лицензионный гейт исключением — отброшено. Уровень 2: сокращения объёма нет — замена elk→dagre не выкидывается, а остаётся в задачах, которые владеют кодом рендера (так же её размещают спека и план — нормативные документы оператора); AC issue («в бандле нет elkjs», «ресурсы доступны хостам для Link/Inline») целиком в #42. Лицензии: решение по EPL-2.0 уже принято оператором (спек 12, Р29), здесь только его исполнение; безопасность не ослабляется (`ignore-scripts`, гейт в CI — усиление). Эскалация не требуется. Уровень 3: (1а) — ноль нового кода в #42 и ноль новых сущностей; цена — одна строка-регулярка в двух хостах, уже предусмотренная спекой и закрепляемая фикстурой в #43. (2б) — pnpm уже выбран стеком и скриптом лицензий, override делает `pnpm why elkjs` из спеки буквально пустым и избавляет от исключений в гейте. (3б) — «сборка падает» без CI не гейт, а пожелание; `npm-licenses` всё равно требует установки, поэтому pnpm в job lint неизбежен, а esbuild сверху стоит секунды. (4а) — YAGNI: auto-render отвергнут спекой, остальное никто не запрашивал.
  - Неустранённый край (одинаков для всех вариантов 1): заголовок `flowchart-elk` и `flowchart.defaultRenderer: 'elk'` регулярка из плана не покрывает — такие диаграммы упадут с ошибкой заглушки; редкий случай, решается в #43, если всплывёт. Непроверенная подсказка для #43: вместо регулярки mermaid даёт штатный механизм `secure: [..., 'layout']` в `initialize` (ключи из `secure` удаляются из frontmatter-config и `%%{init}%%`) — проверить на 12.2.0 перед использованием.

## Итог после ревью

- **Замена `layout: elk*` → dagre (п. 1):** без изменений. В #42 — заглушка `packages/vendor/elk-stub.js` с контрактом для хостов, плагин esbuild и проверка metafile; регулярка, фикстуры `features/mermaid.md`, `features/mermaid_elk.md` и проверка рендера — в #43 (и #53 для `--view`). Непокрытые края (`flowchart-elk`, `flowchart.defaultRenderer: 'elk'`, подсказка `secure: [..., 'layout']`) — тоже в #43.
- **pnpm (п. 2):** без изменений по сути; pnpm 12 в `packages/vendor/pnpm-workspace.yaml` кроме `overrides: { elkjs: "-" }` требует `allowBuilds: { esbuild: false }` (иначе `ERR_PNPM_IGNORED_BUILDS`), а override всегда записывается в `pnpm-lock.yaml` секцией `overrides` — пакета `elkjs` в lockfile нет. Проверка уязвимостей стека — `pnpm -C packages/vendor audit`.
- **Гейт (п. 3):** `vendor` в `just lint` перед `npm-licenses`. В CI pnpm ставится не action, а `npm install -g pnpm@12.15.0` в существующем шаге (точная версия, без новых actions); находка zizmor `adhoc-packages` подавлена комментарием с причиной.
- **Состав `dist/` (п. 4):** без изменений — `katex.min.css`, `katex.min.js`, `fonts/`, `mermaid.min.js`, `mermaid.min.js.LEGAL.txt`.
